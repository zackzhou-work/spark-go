# Grok Bot 角色的“2D 画面、3D 感觉”：调研与可借用做法

调研日期：2026-10-31。范围：Grok Bot 吉祥物的造型度量、动作语言、状态集合，以及它们如何落到 spark-go 的字符（26–40px、mygo 立即模式绘制）上。本文只有调研，没有改产品代码。

## 1. 结论

Grok Bot 之所以“平面但有立体感”，不是靠贴图或阴影，而是靠一条规则：**眼睛是贴在球面上的点，而不是画在平面上的两个圆**。视图里看得见的一切立体线索都从这条规则派生：

1. 眼睛的位置 = 球面点做正交投影（`x,y` = 方向向量的水平分量）；
2. 眼睛的形变 = 同一球面点的切向基被一起投影，所以越靠边缘越窄（风缩）；
3. 眼睛的深度 = 方向向量的 `z`，用来微调大小与遮挡前后的顺序；
4. 两只眼睛以 ±半个夹角绕竖轴分开，所以转头时两只眼睛**不是同步平移**，而是成对绕球转——远侧眼会往轮廓里收、变窄；
5. 身体轮廓本身就是一条“极径表”，旋转、挤压、变形都在这张表上做，于是“绕轴转一圈”在 2D 里也能被读懂。

作者的公开说法印证了这套结构：图标“完全是代码做的，每个状态、形状和表情都能平滑变形成另一个”。也就是说角色是**一个连续参数空间**，不是一个状态一个关键帧。

对 spark-go 的直接结论：现在只有眼睛在动，缺的不是“帧数”，而是**球面约束 + 身体姿态（倾/转/呼吸）**这两层。补上这两层，26px 也能读出立体感；不补，画到 60fps 也还是贴纸。

## 3. 造型基线（从官方 mark 量出来的）

viewBox `-15 -15 259 259`，身体填充 `#0A0A0A`，两只纯白眼。

| 项 | 值 |
| --- | --- |
| 身体包围盒 | 228.5 × 248.7（底部有一处 −10 的外凸缺口，不是标准圆） |
| 身体质心 | (114.3, 114.2) |
| 近（左）眼 | 相对中心 (+22.4, −47.5)，距中心 52.5，方位 64.7° 仰角 |
| 远（右）眼 | 相对中心 (+71.7, −56.8)，距中心 91.5，方位 38.4° 仰角 |
| 两眼连线 | 仰角 10.8°，间距 50.1 |
| 眼形 | 胶囊，长轴 −63°（相对水平，即距垂直 27°），近眼 31.4×42.0，远眼 26.9×41.0 |
| 远眼风缩 | 宽比 0.86，面积比 0.66 |

两点值得注意，也是整个“3D 感”的静态基础：

- **两眼不对称于竖中线**。远眼更高、更靠外、更小。静态 mark 里就写着“这张脸是转过去的”。
- **两眼是同一个装订角**（−63°），不是各自朝不同方向斜。成对倾斜比各自倾斜更像一个整体绕轴转。

复刻样品把这两个数落成了参数：`REST_GAZE = {yaw 28.49°, pitch 28.62°, roll −13°}`，`EYE_SPLIT = 15.46°`（两眼各绕竖轴 ±半个夹角），眼椭圆半轴 0.186 × 0.412（单位球半径）。与 mark 的量值同量级，可作为我们自己的初值。

## 4. 立体感的五个机制

### 4.1 眼睛在球面上（核心）

复刻样品的实现只有十几行，但它把所有线索一次性给全：

```js
// f=前, right=右, down=下，三个基向量
[f, right] = spin(f, right, yaw)      // 绕竖轴
[down, f]  = spin(down, f, pitch)     // 绕横轴
[right, down] = spin(right, down, roll) // 绕视轴

// 每只眼睛：以 ±split/2 绕竖轴分开
[ef, er] = spin(f, right, ±split)
eye = {
  x: ef.x * r, y: ef.y * r,      // 中心 = 球面点正交投影
  a: er.x, b: er.y,              // 眼的“横轴”= 切向基的投影（自动风缩）
  c: down.x, d: down.y,          // 眼的“竖轴”
  depth: ef.z,                   // 深度：越靠边越小
}
```

关键点是 `a,b` 不是常数：它就是切向量被投影后的长度，所以往边上转时眼睛会自己变窄，**不需要另写一套“透视缩放”**。而 `depth` 给了第二条线索（大小/明暗/层序）。

### 4.2 轮廓是极径表

身体不是矩形/圆形拼的，而是一张 64 段的极径数组（`EGG`、`HEX`、`TRI` 都是同一张表的取值）。于是：

- 变形 = 两张表按 `easeOutCubic` 插值；
- 旋转 = 同一张表绕中心转（配合 `cx,cy` 偏移做公转）；
- 挤压 = 对表做各向异性缩放，体积大致守恒。

这颗“鹅卵石”因此可以有转、滚、翻、变成蛋/六边形，而每一步都还在同一个形状空间里。

### 4.3 体积守恒的挤压与拉伸

呼吸 ±0.5%（周期 3.4s），表现为 `scale(1+e, 1−e)`；开心时横向 +5%、纵向 −4.5%。反过来做（整体放大）就立刻变成“贴纸在缩放”。

### 4.4 分层的小动作叠加

同一帧里同时叠加：呼吸、朝向游走（三段正弦叠加的 `loopNoise`）、整体漂移（半径的 0.6%、0.7%）、眨眼。各自周期互质（11.3s / 3.7s / 9.1s / 4.3s / 13.7s / 7.9s / 5.3s / 3.4s），所以看起来永不重复。实测幅度：

| 动作 | 幅度 | 周期 |
| --- | --- | --- |
| 眼/头 yaw 游走 | ±5.5° + ±1.6° | 11.3s / 3.7s |
| pitch 游走 | ±4.2° + ±1.3° | 9.1s / 4.3s |
| roll 游走 | ±2.2° | 13.7s |
| 整体漂移 | 0.6% / 0.7% 半径 | 7.9s / 5.3s |
| 呼吸 | ±0.5% | 3.4s |

### 4.5 节奏与缓动

- 统一 `easeOutQuint`，明确写死“**身体不过冲**”。身体弹一下是玩具感，不是角色感。
- 状态间 morph 0.4–0.6s；眨眼 0.18s（下落 0.45、回弹 0.55），间隔 1.9–4.6s 随机，18% 概率 0.24s 后再眨一次。
- 转头时头身跟随的增益只有 1.6×/1.1×——眼睛动得多，身体动得少。

## 5. 状态集合

官方影片/复刻样品（14 个）：`idle·wink·wide·thinking·notify·sleep·egg·hexagon·play·orbit·burst·comet·alert·exclaim`。其中 `orbit`/`burst` 就是我们说的“工作的时候会转动”：轮廓一边自转（1.25–2 圈）、一边沿小圆周公转，同时眼睛以 65°/s 的 yaw 扫描，末尾再切回球体。

Novra 的外延更贴近产品语义：`greeting·working·error·finished·upload·restart`，外加可玩交互 `follow（带延迟跟随光标）·annoyed·slap·dizzy`。他们给出的判断标准值得抄：

> 一个角色“在工作”很好做；“一边工作一边还能被打断、被惹烦、被打完继续正确工作”才难。状态共存逻辑先画清楚，再进 Rive 做状态机。

以及产品层面的取舍：**一个角色给足空间，其余只留一张脸**——“几个 agent 同时在跑时，真正的问题不是某个 bot 在干什么，而是哪一个在等你”。

## 6. 映射到 spark-go：差在哪

现状（`avatar.go`）：

- `pose` 只有 `squash / blink / glance / nudge / bubble / badge`，**没有朝向，也没有身体姿态**；
- `glance` 是一维左右平移（`glanceSpan` 260ms、每 2.9s 一轮），眼睛不风缩、不成对旋转；
- 8 个固定形状 × 11 色，切换是“旧表情挤掉、新表情长出来”（`faceShift` 240ms），形状本身不变形；
- 眨眼靠 `seed%period` 定时，3520–5200ms 一次；
- 绘制在 26 / 30 / 34 / 36 / 40px 五档，`u = r.W/64`。

差距按“立体感贡献”排序：

| 差距 | 立体感贡献 | 改动面 |
| --- | --- | --- |
| 眼睛没有球面约束（不风缩、不成对转） | 高 | `pose` + `paintFace` |
| 身体不跟朝向（不倾、不转） | 高 | `paintAvatar` 的 `body.rotate` / 新增 roll |
| 没有体积守恒的持续呼吸 | 中 | `idle` |
| 工作态只有平移，没有“转一圈” | 中（辨识度最高） | `idle` + 形状轮廓采样 |
| 分层游走（多周期叠加） | 中 | `idle` |
| 形状不能互相变形 | 低（当前产品不要求） | 需要统一极径表，成本大 |

## 7. 建议的分层改造

### P0（最小可用，1–2 天）

1. **眼睛上球面**：`pose` 用 `yaw/pitch/roll` 三个角度代替 `glance`；在 `paintFace` 里按 §4.1 算每只眼的中心、横轴长度（风缩）与 tilt，喂给现有的 `s.ellipse` + `spin`。26px 下 `u≈0.4`，一只眼的横轴变化 15% 只有 0.6 设备像素——所以**要同时改 tilt 和位置**，单靠宽度看不出来。
2. **身体跟头**：`body.rotate` 加 `roll*0.6`，`cy` 加 `pitch` 的 1–2% 作为点头位移。滚动是最便宜、最抗缩放的立体线索。
3. **体积守恒呼吸**：`squash` 乘 `(1±0.006, ∓0.006)`，周期 3.4s，与现有 `sy` 轴一致。
4. **分层游走**：把 `glance()` 换成三个互质周期的正弦叠加，幅度按 §4.4 的 1/3 缩（26px 只留大轮廓）。

### P1（“工作时会转动”，2–3 天）

5. `moodWorking` 专属循环：身体绕竖轴慢转。2D 实现不必真转 3D——把形状的极径表按 `sin(yaw)` 做一次**左右非对称偏移**（等效于轮廓一侧被压窄）就能读出转轴；再叠 ±3° 滚动。
6. 眼睛在转动时保持“粘在球上”（§4.1 自动成立），到转动端点时切换到扫视。
7. 眨眼改成随机间隔 1.9–4.6s + 18% 双眨，节奏与 §4.5 对齐。

### P2（可选）

8. 只给“聚焦中/悬停”的角色全速动，其余降频（见 §8）。
9. 形状之间做极径表插值，为以后“表情=形状+表情”留口。

## 8. 约束与风险

- **尺寸**：26px 下可用信息量约 3–4 个设备像素。P0 的位移/旋转幅度必须按 §7 的档位裁剪，不能直搬 Grok 的角度。
- **重绘成本**：`Painter.After`/`AnimationFrame` 只重画本帧画过的元素，但持续动作等于每帧都有重绘。`view.go` 里角色墙一次可画 40+ 个角色（`avatarOf(..., moodCaughtUp, ...)`），全部持续动会长时间占 CPU。Grok 自己的答案是“一个聚焦、其余只留一张脸”，我们可以照抄成：**只有悬停/聚焦的那一个全速动，其余用事件式脉冲（每 3–5s 一次小幅动作 + 眨眼）**。
- **可达性**：`ReduceMotion` 下已经走静态分支，新动作必须继续遵守；呼吸/游走属于“装饰性动作”，减动时全部关掉，只保留状态切换。
- **身份**：不引入 Grok 的 mark、不改 8 形状 11 色的调色板；借的是运动学，不是外观。

## 9. 不建议做的事

- 不做真 3D 网格/光照（mygo 是 2D 光栅，成本与收益不成比例）；立体感来自约束与姿态，不来自着色。
- 不给未聚焦角色加“打招呼/被戳/生气”这类交互戏码——spark-go 的字符是状态指示器，不是可玩的宠物；被戳了要回应的期待会立刻变成 bug 报告。
- 不做形状之间的连续变形（当前 8 形状是用户选的身份，变形会削弱辨识）。
- 不要过冲。角色感的来源是“慢半拍”和“不过冲”，不是弹性。

## 11. 落地：Go 里的实现（P0 + 指针跟随）

改在 `avatar.go`，`pose` 多出 `gaze`（yaw/pitch/roll）与 `breath`；`glance` 与它的一维平移被删掉。

- 眼睛的落点由 `gaze.eyes(dx, rx, ry)` 算：把眼睛当成半径 32 设计单位的球面上的点，两只眼先各绕竖轴分开 `asin(dx/32)`，再随脸的 yaw/pitch 转，取正交投影。宽比取"自身横轴被投影后的长度"，靠边的那只自己变窄，不需要另写透视。靠近轮廓时把眼心夹回 `32 - rx` 以内，避免眼睛越过身体的边。
- `pitch > 0` 是往下看：`y = -on.y*32`，所以正的 pitch 把眼睛推到中线下方；正的 `yaw` 把眼睛推到右侧（这两个方向都有测试守着：`TestGazeLooksTheWayItSays`）。
- `roll` 不做进眼睛，而是转整张脸（`gaze.lean() = -roll`），因为绘制里正的 rotate 是顺时针，而右手系里的正 roll 是逆时针——符号反了就会看到"眼睛和身体朝相反方向歪"。这是第一版画布里最别扭的地方。
- 眉毛跟着眼睛的平均位移走，否则转脸时眉毛留在原地。
- 呼吸用体积守恒：`sx = 1+breath`、`sy = 1-breath`（1%）。
- 游走 `drift()`：三层正弦叠加，周期 6.3 / 2.9 / 5.1 / 3.1 / 8.7 秒，幅度按表情分档（工作 9°/5°/4.5°，需要你 11°/4°/5°，完成 5.5°/3.5°/2.4°，未知 1.4°/1°/0.8°），每个角色另有 −2.7…+2.7° 的静止偏置。工作态再叠一层 5.7 秒、±4.5° 的慢扫视。
- 指针跟随 `gaze.toward()`：三倍身宽内开始生效，用 smoothstep 混入游走，30°/22° 封顶。角色会"注意到你"，但不会一直盯着。
- 重绘：工作/需要你/待读 33ms 一帧，完成/未知 99ms 一帧（它们动得本来就少）。`ReduceMotion` 下全部关掉，只留状态切换。

**没做**：真正的"转过去"（Grok 在自转那段把眼睛关掉，2D 里要伪造这个转折点；等 P1 再说）。也没有形状之间的变形。

校验方式：`AVATAR_POSES_PNG=/tmp/poses.png go test -run TestAvatarPoses .`（方向）、`AVATAR_DRIFT_PNG=/tmp/drift.png go test -run TestAvatarDriftSheet .`（真实尺寸下的动作幅度）。看窗口用 `go run . --avatars`。

实测：840×760 的角色墙（约 120 个角色同时在动）约 2.1ms 一帧，30fps 下占预算的十分之一。

### 11.1 身体也跟着转（2026-10-31 续）

眼睛跟着光标还只是一半。Grok 的角色是 3D 网格，转身时*投影*会变，所以第二版让身体自己变：

- `gaze.bodyTurn()` 给出两个量：`squeeze`（整体宽度 ×0.9–1.0）和 `turn`（有符号，±0.55·sin(yaw)）。`shape.at()` 里对每个点做一次弯折 `x -= turn·x²/32`：转身那侧的边缘被压进去、面向你的一侧保持宽度。圆形几乎不变（符合球体投影），方形、星形、爱心变得很明显。
- 眼睛的落点也走同一个弯折，并把眼心夹在弯折后的轮廓里——否则身体一侧收进去、眼睛还挂在外面。
- 眉毛、嘴、闭眼线用 `faceOffset()` 取眼睛的平均位移，跟着脸走。
- 精度上的取舍：这是"平片投影"的近似，不是真的网格。真 3D 需要网格与光照，2D 光栅里不划算；能借的只有"边缘被压进去"和"远侧变窄"这两条。

### 11.2 帧率（这一版最容易翻车的地方）

- `Painter.After(d)` 是"定时器 + 等下一帧刷新"，在 120Hz 屏上实际间隔会是 16.6/25ms 交替 —— 慢速漂移看不出来，但快速跟随时就是"卡卡的"。
- `Painter.AnimationFrame()` 直接跟着刷新走，间隔均匀；代价是整窗按刷新率重画。
- 结论：**漂移用 `After(33ms)`，指针进入范围时切 `AnimationFrame()`**。实测 360×640 列表 8 个角色 2.5ms/帧、20 个 6ms/帧；840×760 的 120 个角色墙约 28ms/帧，所以 `--avatars` 那个调试窗在被指着的时候会掉帧，是窗口太贵，不是动画本身。
